# qrcart

**qrcart** は、会員証の QR コードでログインして商品を申し込む、シンプルな Web システムです。
展示会・社内販売会・イベント会場などで、タブレットやスマートフォンを受付端末として使うことを想定しています。

> **English summary** — qrcart is a lightweight PHP + MySQL ordering system where members log in by
> scanning a QR code, pick items from a catalog, and place orders. It includes an admin panel for
> orders, members, items (with CSV import/export), stock management, printable receipts (configurable paper width),
> and optional Google Chat notifications. All assets are bundled locally, so it can run on a closed
> intranet with no Internet access. The UI is in Japanese.

## 特長

- PHP 8.3 + MySQL 8.0 のみで動作 (フレームワーク・Composer 不要。PHP 拡張 `pdo_mysql`・`mbstring` が必要)
- Bootstrap 5 / html5-qrcode をローカル同梱 (インターネット接続不要)
- カメラまたは USB ハンディスキャナで QR コードログイン
- 商品・会員の CSV 一括取込 (変更内容のプレビュー付き)
- 在庫管理、通常価格・割引表示、メーカー絞り込み
- レシート印刷 (ロール紙・ラベル紙から A4 まで、用紙幅を設定可能)
- Google Chat Incoming Webhook による申込み通知
- UI はすべて日本語

## セットアップ手順

### 1. 接続設定ファイルの作成

`qrcart-my.cnf.example` をコピーして `qrcart-my.cnf` を作成し、接続情報を記入します。

```sh
cp qrcart-my.cnf.example qrcart-my.cnf
chmod 600 qrcart-my.cnf
```

```ini
[client]
host     = 127.0.0.1
port     = 3306
user     = qrcart
password = change-me
database = qrcart
```

パスワードは記号を含めてそのまま書けます。`;` や `"` を含む場合や前後に空白がある場合は、
`password = "パスワード"` のようにダブルクォートで囲んでください。

アプリケーションは既定でリポジトリ直下 (`public/` の1つ上) の `qrcart-my.cnf` を読みます。
**Web 公開ディレクトリの外**に置いてください。別の場所に置く場合は、環境変数
`QRCART_DB_CNF` にフルパスを設定します (例: Apache なら `SetEnv QRCART_DB_CNF /path/to/qrcart-my.cnf`)。

たとえば `public/` の中身を公開ディレクトリのサブフォルダ (`~/www/qrcart/` など) に置くと、
その1つ上 (`~/www/`) にある `qrcart-my.cnf` が Web から見えてしまうことがあります。
万一に備えて、リポジトリ直下の `.htaccess` (`*.cnf`・`*.log` への直接アクセスを禁止) を
**`qrcart-my.cnf` と同じディレクトリに置いてください** (Apache の場合)。
既にそのディレクトリに `.htaccess` がある場合は、中身をその末尾に追記してください。

`qrcart-my.cnf` は `.gitignore` 済みのため、誤ってコミットされることはありません。

#### ログフォルダ (`log/`)

エラーなどのログは、リポジトリ直下 (`qrcart-my.cnf` と同じ場所) の `log/` に月ごとのファイル
(例: `log/qrcart-2026-10.log`) で保存されます。サーバーには `log/` フォルダ (中の `.htaccess` を含む) も
アップロードし、PHP から書き込めるようにしてください (フォルダがない場合は自動で作成を試みます)。
`log/` に書き込めない場合は、PHP の通常のエラーログに出力されます。

うまく動かないときは、まずこのログを確認してください。データベースに接続できない場合などは、
管理画面 (`/admin/`) を開くと原因と対処方法が画面に表示されます
(利用者画面には「ただいまご利用いただけません」とだけ表示され、詳細は表示されません)。

| 環境変数 | 内容 | 既定値 |
|---|---|---|
| `QRCART_DB_CNF` | 接続設定ファイルのフルパス | リポジトリ直下の `qrcart-my.cnf` |
| `QRCART_LOG_DIR` | ログの保存先フォルダ | リポジトリ直下の `log/` |
| `QRCART_TIMEZONE` | ログの時刻・申込番号の日付に使うタイムゾーン | `Asia/Tokyo` |

Apache では `public/.htaccess` に `SetEnv 変数名 値` の形で設定できます。

### 2. データベースとテーブルの作成

データベースと接続ユーザーを作成します (共有レンタルサーバー等では管理画面から作成してください)。

```sql
CREATE DATABASE qrcart CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE USER 'qrcart'@'localhost' IDENTIFIED BY 'change-me';
GRANT ALL PRIVILEGES ON qrcart.* TO 'qrcart'@'localhost';
```

`schema.sql` でテーブルとサンプルデータ (会員3名・商品6点) を作成します。

```sh
mysql --defaults-extra-file=qrcart-my.cnf < schema.sql
```

(`--defaults-extra-file` が使えない環境では
`mysql -h <ホスト> -u <ユーザー> -p <データベース名> < schema.sql`)

### 3. 起動

`public/` の中身を Web サーバーのドキュメントルート (公開ディレクトリ) に
配置します。`public/lib/` には `.htaccess` (Require all denied) を置いてあり、
Apache 環境ではブラウザから直接アクセスできません。

Apache を使う場合は `public/.htaccess.example` を `public/.htaccess` にコピーし、
環境に合わせて編集してください (管理画面のパスワード設定は次の「4. 管理画面にパスワードを設定する」を参照)。

PHP ビルトインサーバーで起動する場合 (動作確認用):

```sh
php -S 0.0.0.0:8080 -t public
```

(ビルトインサーバーは .htaccess を解釈しないため、本番運用には使わないでください)

### 4. 管理画面にパスワードを設定する (Basic 認証)

管理画面 (`/admin/`) にはアプリ自体のログイン機能がありません。インターネットから
アクセスできるサーバーでは、必ず Web サーバーの Basic 認証でパスワードを掛けてください。
以下は Apache の場合の手順です。

#### 手順 1: パスワードファイル (`.htpasswd`) を作る

パスワードファイルは **Web 公開ディレクトリの外** (例: ホームディレクトリ直下) に作成します。
公開ディレクトリの中に置くと、ファイルをダウンロードされてパスワードを解析されるおそれがあります。

ファイルは「ユーザー名:暗号化されたパスワード」を1行に1ユーザーずつ書いたテキストファイルです。

```
admin:$2y$05$Q3Zc...(暗号化されたパスワード)
```

次のいずれかの方法で作成してください。

**方法 1: `htpasswd` コマンドを使う (SSH が使える場合・推奨)**

```sh
# ファイルを新規作成 (-c) して、ユーザー admin を追加 (-B = bcrypt 方式で暗号化)
# パスワードは画面の指示に従って2回入力します
htpasswd -c -B /home/<ユーザー名>/qrcart.htpasswd admin

# 2人目以降を追加する場合は -c を付けない (付けるとファイルが作り直され、既存ユーザーが消えます)
htpasswd -B /home/<ユーザー名>/qrcart.htpasswd staff

# パスワードを変更する場合も同じコマンド (-c なし) を実行します
# ユーザーを削除する場合
htpasswd -D /home/<ユーザー名>/qrcart.htpasswd staff
```

**方法 2: PHP で作る (`htpasswd` コマンドがない場合)**

```sh
php -r 'echo "admin:" . password_hash("ここにパスワード", PASSWORD_BCRYPT) . PHP_EOL;' > /home/<ユーザー名>/qrcart.htpasswd
```

2人目以降は `>` を `>>` に変えると追記されます。この方法ではパスワードがシェルの
コマンド履歴に残るため、実行後に履歴から削除してください (bash なら `history -c`)。

**方法 3: レンタルサーバーのコントロールパネルを使う**

多くのレンタルサーバーには「アクセス制限」「パスワード保護」などの機能があり、画面操作で
`.htpasswd` と `.htaccess` を作成できます。この方法で `admin` フォルダを保護した場合は、
手順 2 の Basic 認証の設定は不要です (`public/.htaccess` の Basic 認証部分は削除してください)。

> Web 上の「htpasswd 生成サイト」は、パスワードを第三者のサーバーに送信することになるため
> 使わないでください。

作成したファイルは Web サーバーが読み取れる権限にしておきます
(多くの環境では `chmod 644`。詳しくはサーバーのマニュアルを参照してください)。

#### 手順 2: `.htaccess` でパスワードファイルを指定する

`public/.htaccess` (`public/.htaccess.example` をコピーしたもの) を開き、`AuthUserFile` に
手順 1 で作ったファイルの **フルパス** を書きます (相対パスは使えません)。

```apache
AuthType Basic
AuthName "qrcart admin"
AuthUserFile /home/<ユーザー名>/qrcart.htpasswd

<If "%{REQUEST_URI} =~ m#/admin(/|$)#">
    Require valid-user
</If>
```

ホームディレクトリのフルパスは、SSH で `pwd` を実行するか、サーバーのコントロールパネルで確認できます。

#### 手順 3: 動作を確認する

1. ブラウザで `/admin/` を開くと、ユーザー名とパスワードの入力画面が表示されます。
2. 手順 1 で登録したユーザー名・パスワードを入力すると、管理画面が表示されます。
3. 利用者画面 (`/`) はパスワードなしで表示されることも確認してください。

**うまくいかないとき**

| 症状 | 主な原因 |
|---|---|
| 入力後に 500 エラーになる | `AuthUserFile` のパスが間違っている、またはファイルを読み取る権限がない (`AuthUserFile` が例の `/path/to/...` のままになっていないか確認) |
| 正しいパスワードでも入れない | ファイルの内容が壊れている (余分な空白・改行など)。方法 1 で作り直してください |
| パスワードを聞かれない | `.htaccess` が読み込まれていない (サーバーが `.htaccess` を許可しているか確認) |

詳しい原因はサーバーのエラーログに記録されます (例: `Could not open password file`)。

Basic 認証のパスワードは暗号化されずに送信されるため、必ず HTTPS (下記「方法 B: HTTPS 化する」) と組み合わせて使ってください。

## セキュリティ

- **管理画面 (`/admin/`) にはアプリケーション自体の認証がありません。**
  インターネットに公開する場合は、必ず Web サーバー側で Basic 認証・IP 制限等を設定してください
  (手順は「セットアップ手順」の「4. 管理画面にパスワードを設定する」を参照)。
- 会員の QR コード値はログイン用の秘密情報です。推測されにくいランダムな値を使用してください
  (会員管理画面の追加フォームでランダム値が自動提案されます)。
- 本番環境では HTTPS で運用してください (カメラ API の利用にも HTTPS が必要です)。

脆弱性を見つけた場合は [SECURITY.md](SECURITY.md) の手順で報告してください。

## 会員QRコードの作り方

会員の追加・編集・削除は管理画面の「会員管理」(`/admin/users.php`) で行います。
追加フォームにはランダムなQRコード値が自動で提案されます
(申込履歴のある会員は削除できません)。

登録した `qr_code` 列の文字列を、そのまま QR コード化して配布します。
サンプルでは `MEMBER-0001-7f3a9c` などが登録済みです。
qrencode コマンドが使える場合:

```sh
qrencode -o member1.png "MEMBER-0001-7f3a9c"
```

会員管理画面では CSV での一括操作も可能です。

- **CSVエクスポート**: 登録済み会員 (id, qr_code, name, 申込み数) を CSV でダウンロードします。
- **CSVアップロード (追加・更新)**: 来場者リスト (`受付番号`・`会社名`・`氏名` の列を含む CSV) を
  取り込みます。受付番号を QR コード値、「会社名 | 氏名」を氏名とします (会社名が空なら氏名のみ)。
  QR コード値が既存の会員と一致する行は氏名が違えば更新し、一致しない行は新規追加します。
  CSV に含まれない会員は変更されません。
- **CSVアップロード (全置換)**: `qr_code` 列と `name` 列を含む CSV (CSVエクスポートと同じ形式。
  テンプレートファイルもダウンロード可能) で、会員一覧を CSV の内容と一致させます
  (QR コード値で照合し、CSV にない会員は削除)。ただし申込履歴のある会員は削除できないため残ります。
  誤操作を防ぐため既定では無効で、「設定」で有効にしてから使います。

どちらのアップロードも、追加・更新・削除される会員のプレビューが表示され、
「この内容で反映する」を押すまで会員一覧は変更されません。
受付番号のような連番を QR コード値にすると他人の値を推測されやすいため、注意してください。

## ⚠️ カメラ利用に関する重要な注意 (Android)

ブラウザのカメラ API (`getUserMedia`) は **HTTPS でないと動作しません**
(`localhost` を除く)。閉域イントラネットで `http://192.168.x.x` のように
アクセスする場合、次のいずれかの対応が必要です。

**方法 A: 端末側で例外設定する (台数が少ない場合に簡単)**

Android の Chrome で `chrome://flags/#unsafely-treat-insecure-origin-as-secure`
を開き、`http://<サーバーIP>:8080` を入力して Enabled にし、ブラウザを再起動します。

**方法 B: HTTPS 化する (推奨)**

Web サーバーに SSL 証明書を設定し、HTTPS でアクセスできるようにします
(公開サーバーなら Let's Encrypt やレンタルサーバーの無料 SSL、閉域網なら自己署名証明書や組織内 CA の証明書)。
自己署名証明書の場合、各端末で初回アクセス時に警告を許可するか、証明書を端末にインストールしてください。

あわせて、HTTP でアクセスされたときに自動で HTTPS へ転送されるよう、**常時 SSL (HTTPS へのリダイレクト) を
有効にしてください**。レンタルサーバーではコントロールパネルに「常時SSL化」などの設定が用意されていることが
多いので、それを利用するのが確実です。設定方法はお使いのサーバーのマニュアルを参照してください。

カメラが使えない環境向けに、ログイン画面には QR コード値の手入力欄も
用意してあります (USB 接続のハンディ QR スキャナもこの欄で利用可能)。

ログイン画面で最初に起動するカメラは、「設定」(`settings.php`) の「ログイン画面のカメラ」で
インカメラ (前面) / アウトカメラ (背面) から選べます (既定はインカメラ)。
指定したカメラが存在しない端末では、もう一方のカメラに自動的に切り替わります。
起動後は「インカメラ/アウトカメラ切替」ボタンでいつでも切り替えられます。

## 商品の追加・変更

商品の追加・編集・削除は管理画面の「商品管理」(`/admin/items.php`) で行います。
画像ファイルは `public/assets/img/` にアップロードし、画像パス欄に
`assets/img/ファイル名` の形式で指定します。

任意項目として 商品コード (itemcode)・メーカー (brand)・備考1 (misc1)・備考2 (misc2)・
キャプション (caption)・通常価格 (regular_price) を登録できます。商品コード・備考1・備考2は
管理画面でのみ表示され、利用者には見えません。商品コードは文字列で、重複は登録できません。
キャプションは商品一覧で商品名の下に表示されます。
メーカーは商品一覧で商品名の上に小さく表示され、商品一覧上部の絞り込みにも使われます。

商品管理画面では CSV での一括操作も可能です。

- **CSVダウンロード**: 登録済み商品を CSV でダウンロードします (`id` 列は参考表示用)。
- **CSVアップロード (全置換)**: 商品一覧を CSV の内容と一致させます。`itemcode` 列が
  既存商品と一致する行はその商品を更新し (内部 ID が変わらないため、既存の申込みの在庫引当や
  申込みの再編集に影響しません)、一致しない行・`itemcode` が空の行は新規追加、CSV に
  含まれない商品は削除します。`id` 列は無視されます。
  アップロード後に追加・更新 (変更される列の旧→新)・削除される商品のプレビューが表示され、
  「この内容で反映する」を押すまで商品一覧は変更されません。CSV 内に不正な行
  (`itemcode` の重複、価格が数値でない など) が1行でもある場合は取り込まずに問題の行を表示します。
  Excel の「CSV UTF-8」「CSV (コンマ区切り)」(Shift_JIS) のどちらで保存したファイルも読み込めます。
  キャプションのセル内改行 (Alt+Enter) もそのまま取り込まれます。

通常価格を入力すると (販売価格以上の場合)、商品一覧画面で販売価格の下に
取り消し線付きで表示されます。販売価格より高い場合は「N% OFF」のバッジも表示されます。
空欄の場合や販売価格より低い場合は販売価格のみが表示されます。

`display_order` (表示順) の昇順で商品一覧に表示されます。
商品を削除しても、申込み明細には申込み時点の商品名・価格が保存されているため、
過去の申込みの表示・金額には影響しません。

在庫数 (任意) を設定すると、商品一覧・カート確認画面に残り在庫数が表示され、
在庫を超える数量は申し込めなくなります (在庫切れになると数量入力が無効化されます)。
「無制限」のチェックを外して数量を指定した場合のみ在庫管理が有効になります。
在庫は「未キャンセルの申込みで確保された数量」を元に計算するため、申込みがキャンセル
されると在庫は自動的に解放されます。

## レシート用紙の設定

レシートの用紙は「設定」(`settings.php`) の「レシートの用紙」で指定します。

- **用紙の幅**: 20〜210mm (A4 の幅) の範囲で指定します (既定は 62mm)。
  よく使う幅はボタンで選べます。

  | 用紙 | 幅 | 「長さを内容に合わせる」 |
  |---|---|---|
  | 感熱ロール紙 (小型レシートプリンター) | 58mm | オン |
  | 連続ラベル紙 (例: Brother QL シリーズ + DK-2205) | 62mm | オン |
  | 感熱ロール紙 (標準レシートプリンター) | 80mm | オン |
  | A4 用紙 | 210mm | オフ |

- **用紙の長さを内容に合わせる** (既定: オン): 印刷時にレシートの内容の長さを測り、
  `@page { size: 幅 長さ }` で用紙サイズをちょうどに指定します。連続紙・ロール紙なら
  1件の申込みが1枚のレシートとして、余白なく印刷されます。
  オフにすると用紙サイズはプリンタードライバーの設定に従います (A4 などの定形用紙・カット済みラベル向け)。
- どちらの場合も、内容が用紙1枚に収まらないときは、行の途中で切れないように次のページへ送られます。

プリンタードライバー側の設定:

- 用紙の幅を、設定した幅と同じにしてください (連続紙の場合は「長さ連続」などを選択)。
- 余白は「なし」にしてください。
- ブラウザの印刷ダイアログで「倍率: 100% / 既定」「ヘッダーとフッター: オフ」にしてください。
- ドライバーによっては、ブラウザが指定した用紙サイズを受け付けず、ドライバーの用紙設定で
  印刷される場合があります。初めて使うプリンターでは、まず PDF に保存して用紙サイズを確認し、
  実機でテスト印刷してください。

文字サイズは用紙の幅によらず一定です (A4 など広い用紙では相対的に小さく見えます)。

## 仕様メモ

- ログイン時に既存の申込みがある場合は申込履歴ページが表示され、
  「編集」(内容をカートに読み込んで上書き更新) または
  「追加で申込む」を選択できます。編集して確定すると申込番号はそのままで
  明細・備考・申込日時が更新されます。キャンセル済みの申込みは編集できません。
- 申込み編集中に、カートの最後の商品を削除 (数量0) しようとすると確認モーダルが
  表示され、確定すると `cancel_order.php` が申込みをソフトキャンセル
  (`orders.cancelled_at` に日時を記録) し在庫が解放されます。編集中に内容を
  変更した状態でナビゲーションバーの「申込履歴」やログアウトを押すと、
  編集の破棄を確認するダイアログが出ます (cart.js が localStorage のカートと
  編集開始時の内容を比較して判定)。
- カートは **ブラウザの localStorage** に保持します (`qrcart_cart` /
  `qrcart_remarks`)。共通ロジックは `public/assets/js/cart.js` (`window.qrCart`)。
  ログイン時・「追加で申込む」時・申込み確定後にサーバーが一度きりの指示
  (`$_SESSION['cart_bootstrap']`) を JSON で渡し、cart.js が localStorage を
  クリア/読み込みします。サーバーはカートを保持しません。
- 商品一覧で数量 (+/− ボタンまたは数値入力、初期値 0) を変更すると、通信なしで
  localStorage のカートに反映されます。「カートに入れる」操作はありません。
- カート確認画面 (cart.php) は全商品カタログ + 在庫を JSON で埋め込み、
  localStorage のカートを結合して JS で行を描画します。数量変更・削除・小計・
  合計の更新はすべてページ内で行われ、再読み込みは発生しません。数量を 0 に
  するとその商品は削除されます。
- カート確認画面の備考欄 (最大1000文字) も localStorage に保持され、確定時に
  `checkout.php` へ POST されて申込みに保存されます (管理画面の申込み詳細で確認可)。
- 申込み確定時、cart.php の隠しフィールドでカート JSON を `checkout.php` に送り、
  サーバー側で検証 (`parse_posted_cart()`)・在庫再確認してから保存します。
- ナビゲーションバーのログアウトボタンは誤操作防止のため間隔を空けて配置し、
  押すと確認ダイアログを表示します。
- JavaScript と localStorage が必須です (キオスク端末を想定)。
- 申込み確定時に商品名・単価のスナップショットを `order_items` に保存するため、
  後から商品マスタを変更しても過去の申込み金額は変わりません。
- 申込番号は `YYYYMMDD-申込みID(5桁)` 形式です (例: `20260610-00012`)。
- 在庫数を設定した商品は、申込み確定時にも在庫を再確認します。カート追加後に
  他の利用者の申込みで在庫が減っていた場合は、申込み可能な数量まで自動的に調整され、
  結果が完了画面に表示されます。在庫切れで申込み可能な商品が一つもなくなった場合は
  確定されず、カート確認画面にエラーが表示されます。
- 管理画面の申込み一覧はキャンセル済みの申込みにバッジを表示し、CSVエクスポート
  (申込み明細を1行ずつ、状態・キャンセル日時付きで出力) ができます。
- 利用者画面のタイトル (ナビゲーションバー・ブラウザのタブ・ログイン画面) は
  「設定」(`settings.php`) の「基本設定」で変更できます。空欄の場合は「申込みシステム」です。
- 価格は `1,234円` の形式で表示されます。「基本設定」の「価格接頭詞」「価格接尾辞」で
  販売価格 (および小計・合計) の前後に付ける文言 (例: `(税別)`) を設定できます
  (利用者画面・管理画面・通知で共通)。通常価格には付きません。
  通常価格の前後に付ける文言 (例: `標準価格 `) は「通常価格接頭詞」「通常価格接尾辞」で別に設定できます。
- 管理画面の申込み一覧・申込み詳細から「レシート印刷」(`receipt.php?id=申込みID`) を
  開けます。ヘッダー文言 → 申込番号 → 氏名 → 申込日時 → 商品名/数量 → 備考欄 →
  フッター文言 の順でレイアウトしたページで、開くと自動で印刷ダイアログが表示されます。
  用紙については下の「レシート用紙の設定」を参照してください。
  ヘッダー/フッターの文言は「設定」(`settings.php`) で全レシート共通で
  変更できます (`settings` テーブルに保存)。ヘッダー/フッターでは簡易タグが使えます:
  行頭の `<left>` `<center>` `<right>` で配置 (既定は中央、指定行以降に継続)、
  `<bold>…</bold>` (または `<b>`) で太字、`<large>` `<xlarge>` `<small>` で文字サイズ。
  設定画面にはツールバーのボタンとライブプレビューがあります。
- 申込みが確定 (新規・変更) されると、設定した Google Chat の Incoming Webhook へ
  通知を送ります。メッセージには申込番号・氏名・点数・合計と、レシート印刷ページ
  (`receipt.php?id=...`) / 申込み詳細ページへのリンクが含まれます。印刷担当者は
  スマホ/PC の通知からリンクを開き、そのまま印刷できます。「設定」画面で
  Webhook URL を登録します (空欄なら通知は送信されません)。通知の送信に失敗しても
  申込み完了処理は止まりません (失敗はログフォルダ `log/` に記録されます)。
    - 完全自動印刷にしたい場合は、プリンターをつないだ PC で未印刷の申込みを
      ポーリングし、ヘッドレス Chrome + SumatraPDF 等で `receipt.php` を無人印刷する
      仕組みを別途用意します (アプリをクラウド/レンタルサーバー上で動かす場合、
      会場のプリンターに直接到達できないため、印刷は会場側の PC から行う必要があります)。
